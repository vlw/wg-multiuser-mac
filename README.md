# WGMenu

Значок WireGuard в строке меню macOS, который держит **несколько туннелей одновременно** и позволяет управлять ими **всем пользователям Mac без пароля администратора**.

Официальное приложение WireGuard для macOS включает только один туннель за раз, и его туннели привязаны к пользователю. WGMenu работает поверх `wg-quick`: каждый туннель получает свой `utun`-интерфейс, поэтому рабочие сети с разными подсетями доступны одновременно. Туннели общие для всей системы: если один пользователь включил сеть, другой после смены пользователя видит её включённой и может выключить.

## Возможности

- Галочки в меню строки меню: включить или выключить любой набор туннелей.
- Окно управления в стиле приложения WireGuard:
  - статус, публичный ключ, адреса, DNS, Endpoint и разрешённые IP;
  - статистика в реальном времени: последнее рукопожатие и трафик ↓/↑;
  - подсказки, что не так: «нет рукопожатия», «связь потеряна», предупреждения про `DNS` и `0.0.0.0/0`;
  - редактор конфига с подсветкой и проверкой ошибок прямо во время набора;
  - создание, переименование и удаление туннелей;
  - импорт файлов `.conf` и zip-архива, выгруженного из WireGuard.
- Журнал: кто, когда и какой туннель включал, вместе с выводом `wg-quick`.

## Требования

- macOS 14 или новее.
- [Homebrew](https://brew.sh) и `wireguard-tools`:
  ```bash
  brew install wireguard-tools
  ```
  Вместе с ним ставятся `wg`, `wg-quick`, `wireguard-go` и bash 5, который нужен `wg-quick`.
- Xcode или Command Line Tools: `swiftc` нужен для сборки.
- Учётная запись администратора для установки.

## Установка

```bash
git clone <repo-url> wg-multiuser-macos
cd wg-multiuser-macos
./install.sh
```

Скрипт собирает приложение и помощник, затем один раз спрашивает пароль администратора и устанавливает:

| Что | Куда |
|---|---|
| Приложение | `/Applications/WGMenu.app` |
| Помощник (запускается от root) | `/Library/PrivilegedHelperTools/wgmenu-helper` |
| Правило sudo | `/etc/sudoers.d/wgmenu` |
| Автозапуск у каждого пользователя | `/Library/LaunchAgents/local.wgmenu.plist` |
| Каталог конфигов (`root:wheel`, `700`) | `/etc/wireguard` |

По умолчанию управлять туннелями может группа `staff`, то есть все обычные локальные пользователи. Чтобы ограничить доступ, создайте свою группу и укажите её при установке:

```bash
ALLOW_GROUP=wgusers ./install.sh
```

Повторный запуск `./install.sh` обновляет установленную версию.

## Добавление туннелей

**Из приложения WireGuard.** В WireGuard выберите *File → Export Tunnels to Zip…*, затем в WGMenu: *Управление туннелями… → «+» → Импорт из файла*. Имена туннелей приводятся к виду, который принимает `wg-quick`: латиница, цифры, `_=+.-`, не длиннее 15 символов. Например, «Работа Москва» станет `Rabota-Moskva`.

То же самое из терминала:

```bash
./import-zip.sh ~/Desktop/wireguard-export.zip
```

**Вручную:**

```bash
sudo install -o root -g wheel -m 600 work.conf /etc/wireguard/
```

После импорта удалите zip-архив: в нём лежат приватные ключи.

## Несколько туннелей одновременно: на что обратить внимание

- **Подсети не должны пересекаться.** В `AllowedIPs` указывайте только сети, которые нужны через этот туннель.
- **Только один туннель с `0.0.0.0/0`.** Такой туннель забирает весь трафик.
- **`DNS =` в нескольких конфигах конфликтует.** На macOS `wg-quick` заменяет системный DNS, и туннели будут перебивать друг другу настройки. Лучше убрать `DNS` из конфига и прописать DNS для внутренних доменов отдельно:
  ```bash
  sudo mkdir -p /etc/resolver
  echo "nameserver 10.0.0.1" | sudo tee /etc/resolver/corp.example.com
  ```
- **Не включайте один и тот же туннель одновременно в WireGuard и в WGMenu.** Два интерфейса с одним ключом будут мешать друг другу.

## Права и безопасность

Приложение работает с правами пользователя. Всё, что требует root, делает помощник, а запускать его без пароля разрешает правило sudo. Помощник принимает только фиксированный набор команд и сам проверяет имена туннелей и содержимое конфигов.

| | Администратор | Обычный пользователь |
|---|---|---|
| Включать и выключать туннели | ✓ | ✓ |
| Видеть статистику и журнал | ✓ | ✓ |
| Изменять адреса, пиры, Endpoint и т. п. | ✓ | ✓ |
| Видеть `PrivateKey` и `PresharedKey` | ✓ | ✗ (показываются как `<hidden>`) |
| Изменять `PreUp`/`PostUp`/`PreDown`/`PostDown`/`SaveConfig` | ✓ | ✗ |

Хуки `PreUp`/`PostUp` выполняются от root. Поэтому менять их может только администратор, иначе любой пользователь получил бы root.

Конфиги лежат в `/etc/wireguard` с правами `600` и принадлежат root. Удалённые туннели переносятся в `/etc/wireguard/.deleted/`, откуда их можно восстановить вручную. Журнал пишется в `/var/log/wgmenu.log`.

## Устройство

```
app/        приложение для строки меню (AppKit + SwiftUI)
helper/     привилегированный помощник: list, caps, get, stats, up, down, create, save, delete, log
shared/     разбор и проверка конфигов wg-quick, общие для приложения и помощника
install.sh  сборка и установка
uninstall.sh
import-zip.sh
```

Помощник можно вызывать и вручную:

```bash
sudo /Library/PrivilegedHelperTools/wgmenu-helper list
sudo /Library/PrivilegedHelperTools/wgmenu-helper stats work
```

## Если что-то не работает

- **В меню написано «Нет доступа к помощнику»:** проверьте, что пользователь входит в группу из `ALLOW_GROUP`, и что работает `sudo -n /Library/PrivilegedHelperTools/wgmenu-helper list`.
- **Туннель не включается:** текст ошибки показывается во всплывающем окне, полный вывод `wg-quick` — в журнале (*Журнал…* в меню).
- **Туннель включён, но «Нет рукопожатия»:** проверьте, что Endpoint доступен, UDP-порт открыт и публичный ключ клиента добавлен на сервер.
- **Значок не появился у другого пользователя:** он появится при следующем входе этого пользователя.

## Удаление

```bash
./uninstall.sh
```

Конфиги в `/etc/wireguard` остаются на месте.
